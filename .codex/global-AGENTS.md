# Personal Codex defaults

Direct user instructions are authoritative. Apply repository guidance from the actual checkout and canonical executable sources. Check the active executor/home, Git root, branch, HEAD and dirty state before repository work; a saved project label or historical path is not evidence of the active checkout.

- Start with the smallest relevant source and a short plan. Continue authorized work in the same session; ask only for missing scope or an action outside authorization. Do not impose a separate plan approval on already authorized implementation.
- Default to one implementation worker. Delegate only when explicitly requested or required by applicable instructions, with isolated branches, disjoint write ownership and a clear integration owner. Pause dependent work when a shared contract is unresolved.
- Preserve the configured model and effort unless the user authorizes a change. Verify current supported options before recommending a different setting; do not guess price or availability. Record observed elapsed time, rework and usage when available, with unknown values left unknown.
- Prefer a small coherent PR. Split at real dependency boundaries; explain unusually large changes and review order. Avoid arbitrary file or line quotas that create invalid intermediate states.
- Run focused checks first, then required repository checks. Reuse passing CI for the exact final SHA. Do not repeat a full matrix locally without a new failure, material change or unmet acceptance criterion.
- Use independent review when required by repository policy or material risk. Bind its result to the exact reviewed SHA and scope. A material change invalidates affected evidence; resolve concrete findings and recheck them. Do not require a fixed number of review rounds.
- Before merge or deployment, verify current HEAD, required checks, review evidence and explicit authorization. Unknown or stale evidence is pending. Do not conflate a draft PR, successful mocked test or prepared artifact with release completion.
- After interruptions, inspect Git state and durable receipts before resuming. Distinguish a worker heartbeat from actual process/descendant status. Preserve recoverable work and provenance before moving branches or cleaning up.
- Deliver a concise result: outcome, branch/PR, base and final SHA, relevant verification, blockers and next action. Add ownership/contracts only when coordinating parallel work; omit empty template fields and long transcripts.
- Promote reusable failures to regression tests or deterministic guards before adding more instructions. Keep transient experiments out of durable memory.

These are personal defaults, not permission to bypass project release gates, broaden spending, install providers, merge or deploy outside the user's scope.
